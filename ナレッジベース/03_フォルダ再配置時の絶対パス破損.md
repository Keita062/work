# フォルダ再配置時の絶対パス破損

## 症状

フォルダを移動・リネームした後、それまで動いていた分析スクリプトが `FileNotFoundError` で落ちる。あるいは**落ちずに古い場所のデータを読んで、静かに間違った結果を出す**。

このリポジトリでは2回発生している。

1. `NEW_SSDSE/` 配下の分析を `SSDSE/02_industry_labor_economics/` へ再配置したとき、`scripts/create_model/` のスクリプトが `NEW_SSDSE` を含む絶対パスを前提にしていて全滅した
2. `SSDSE/01_election_pledges/scripts/election/2025_shu/work/extract_policies.py` が、**別PCの絶対パス**（このマシンには存在しないパス）を参照していて動かなかった

## 原因

Jupyter や単発スクリプトで分析を書き始めると、手っ取り早いので絶対パスを直書きしがちで、そのまま残る。

- フォルダ名がパス文字列の中に埋まっているため、**フォルダを動かした瞬間に全スクリプトが同時に壊れる**
- 別PCで書いたコードを持ち込むと、そのマシンのユーザー名を含むパスがそのまま残る
- git は文字列としてのパスの整合性を検証しないので、**壊れたことがコミット時点では分からない**

## 対処

`__file__` を起点にリポジトリルートを解決し、そこからの相対でパスを組み立てる。`SSDSE/03_unemployment_lca_gis/` のスクリプトはこの書き方で統一されている。

```python
from pathlib import Path

# scripts/model/xxx.py から見て 3つ上がテーマルート
ROOT = Path(__file__).resolve().parent.parent.parent
PROC = ROOT / "data" / "processed"

df = pd.read_csv(PROC / "panel_annual.csv")
```

参考実装: [`SSDSE/03_unemployment_lca_gis/scripts/model/soften_lca_experiment.py`](../../completed_projects/030_ssdse-statistics-competition/03_unemployment_lca_gis/scripts/model/soften_lca_experiment.py)

再配置済みの既存スクリプトを直す場合は、パス修正だけで満足せず、**必ず一度実行して同じ結果が出ることを確認する**。

## 再発防止

- **新しく書く分析スクリプトでは絶対パスを直書きしない。** 上の `Path(__file__).resolve().parent...` の形を使う
- ノートブック（`.ipynb`）はカレントディレクトリ依存になりやすい。**リポジトリルートを作業ディレクトリとして想定している前提**をノートブック冒頭かフォルダの README に明記する
- **フォルダを移動・リネームしたら、そのフォルダ配下のスクリプトを1本は実行して確認する。** パスを直して終わりにしない
- 移動したことと直した範囲を、そのコンペの `Context Vault/Projects/<コンペ名>.md` の残課題に残す（未検証のスクリプトが残っているなら、それも明記する）
