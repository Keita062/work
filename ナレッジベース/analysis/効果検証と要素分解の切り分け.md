# 効果検証と要素分解の切り分け

> 出典：`mbk-digital/set_up`リポジトリのナレッジベースより、案件に依存しない技術知見として移植（2026-10-20）。

## 対象タスク

施策の効果を測る分析設計を作るとき全般。「この施策は効いたのか」を問うドキュメント・
検証設計・報告資料を作る場面で、毎回この切り分けを最初に行う。

## 中核の原則

**「効果検証」と「要素分解」は目的が違う。同じ枠組みに混ぜない。**

| | 効果検証 | 要素分解 |
|---|---|---|
| 問い | 施策は効いたのか | 誰が・どの経路で・どれだけ動いたか |
| 必要なもの | 対照群、または「施策がなかった場合」を代替する比較相手 | 分解軸（セグメント・チャネル・時期など） |
| 言えること | 因果の主張（限定付き） | 内訳の把握、次の打ち手の特定 |
| 言えないこと | 内訳・要因 | **因果。「効いた」とは言えない** |

混ぜると何が起きるか：**対照群を持たない分析が、効果検証として報告されてしまう**。
群を2つ並べた表は見た目が比較に見えるため、読み手も書き手も「差＝効果」と読んでしまう。

## 判別の手順

分析を設計したら、各パートについて次を自問する。

1. **この分析には対照群があるか**（「施策を受けなかったらどうなっていたか」を示す集団）
2. 対照群がないなら、**それは効果検証ではない**。要素分解として、効果検証の外側に置く
3. 群を並べるパートがあるなら、**群の分かれ方は誰が決めたか**を確認する
   - 本人の選択（開封した／設定をONにした／リンクを踏んだ）→ 対照群にならない
   - 抽出条件（料金が前月比1.5倍を超えた等）→ 対照群にならない
   - どちらでもない外的要因・無作為 → 対照群になりうる

## 具体的な注意点

### 「第1段階／第2段階」のような段階表現を避ける

段階と書くと、**両方が同じ目的の工程だと読ませてしまう**。目的が違うなら章を分け、
一方を「効果検証」、もう一方を「追加分析」など別カテゴリの名前にする。
番号の連続は、読み手にとって目的の連続を意味する。

### 対照群のない群比較は「内訳」と呼ぶ

「設定した人としなかった人」のように群を並べる場合、**本文に明示的に
「これは内訳であって比較対照ではない。差を効果と読まないこと」と書く**。
書かないと、数ヶ月後に自分自身が差を効果として引用する。

### 抽出条件で選ばれた対象は無作為ではない

配信対象・施策対象が条件で抽出されている場合、**対象と非対象の差は施策の効果ではなく
抽出条件による偏り**である可能性が高い。とくに抽出条件が「反応しやすさ」と相関する
場合（料金変動が大きい人を選ぶ→もともと反応しやすい層）、差は必ず正に出る。

### 指標を分解するときは目的を明示する

同じ分解でも、目的が「因果の特定」か「伸びしろの可視化」かで、必要な比較相手も
結論の言い方も変わる。**分解する前に「この分解で何を言いたいのか」を1文で書く。**

分解の目的として有力なのは次の2つ。因果の特定より、こちらのほうが成立しやすい。

- **伸びしろの可視化**：施策が働きかけられる母数を切り出し、上限を示す
- **目標の翻訳**：「あとXpt必要」を「あと何人動かす必要があるか」に変換する

### 全体値は直接カウントする。足し上げで作らない

セグメント別の値を足し上げて全体値を作ると、**集計対象から外したカテゴリが
丸ごと抜け落ちて過小集計になる**（例：在籍期間が短く分類不能な層を分析対象から
除外していた場合）。

```
誤： 全体値 = Σ 各セグメントの値
正： 全体値 = 母集団から直接カウント
     Σ 各セグメントの値（除外分を含む） = 全体値   ← 検算に使う
```

足し上げは**検算の向き**で使う。一致しなければ、分類か母集団の切り方が誤っている。

### 限界を先に書く

効果検証の章に「この検証で言えること・言えないこと」を必ず置く。
報告の場で過剰な主張になるのを防ぎ、逆に「因果が示せていない」と突っ込まれたときに
説明に窮するのも防ぐ。**言えることの上限を先に決めておくと、報告の言い回しがぶれない。**

## 適用範囲

施策の効果測定、A/Bテスト設計、KGI・KPIの評価設計、施策の振り返り資料全般。
対照群を置けないケース（施策が全員に一斉展開された、ログが後付けで整備された等）で
とくに重要になる。
