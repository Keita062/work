## 1. 取得メカニズム（実証済み）

e-Stat の「ファイル」型データは、以下の直URLで取得できる（curl / urllib で可）。

```
https://www.e-stat.go.jp/stat-search/file-download?statInfId=<ID>&fileKind=0
```

- `fileKind=0` が実ファイル。多くは **BIFF形式 .xls（OLE2）**。CSV(`fileKind=1`)は無い表が多い。
- `.xls` は **pandas + `engine='xlrd'`** で読める。文字は cp932 だが pandas/xlrd が unicode 化する。**コンソール表示には `PYTHONUTF8=1`** が必要。
- `statInfId` は各データの「ファイル」ページHTMLの `file-download?statInfId=…` から取得（個別ファイルページは静的HTMLでリンクが拾える。tstat一覧ページはSPAで拾えないことがある）。
- 取得スクリプト：[`scripts/collect/fetch_estat.py`](../scripts/collect/fetch_estat.py)（確認済みデータの登録簿つき）。

## 3. 判明した重要事項

- **失業者数の単位は「万人」**（前職の産業別完全失業者数）。人として扱うと失業率が非現実的になるため、就業者数と万人単位で統一する（[fill_unemployment_rate.py](../scripts/preprocess/fill_unemployment_rate.py) で対応済み）。
- **職業安定 2-6 は新規学卒者限定**で、構成概念3（一般の労働需給）には使えない。一般労働者の県×産業求人は公表が限定的なため、構成3は「有効求人倍率（県・全産業＝社会生活統計指標）」や求人側の代替変数で再構成する必要がある（→ §4 のTODO）。
- e-Stat の **DB型（dbview / statdisp_id）** は API なしのWeb取得が難しい。**ファイル型（file-download）** を優先し、DB型しかない指標はファイル版の有無を確認する。
