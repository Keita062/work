# リサーチクエスチョン設定プラン
## 日本の取り組むべき課題の特定分析

**作成日**: 2026年5月11日  
**目的**: 政党人気度を排除した政策課題分析に基づく、リサーチクエスチョンの設定

---

## 1. 分析目的の再定義

### 1.1 最終ゴール
過去二回の選挙（衆議院・参議院）における各政党の公約データを、**政党の人気度・選挙結果を統制した分析**により、日本が取り組むべき**優先課題**を特定し、それに基づくリサーチクエスチョンを設定する。

### 1.2 重要な制約条件
- **人気度の排除**: 得票数や当選者数が多い政党の課題を過度に重視しない
- **非政治的立場**: 特定の政党イデオロギーではなく、課題そのものの構造化
- **複数選挙データの活用**: 衆議院・参議院の異なる制度・時期のデータから共通課題を抽出
- **ポジネガの統合**: 課題に対するポジティブ/ネガティブアプローチの両方を認識
- **選挙性質への配慮**: 衆議院（全国一律）と参議院（地方区・比例）の制度差を考慮

## 3. 分析フレームワーク

### 3.1 Phase 1: データ準備・整形（単純データ化）

#### 目標
- すべての公約データを**統一フォーマットのテキストデータ**に変換
- 衆参別・政党別で整理
- 後段の分析への入力データを準備（課題抽出は Phase 2 で実施）

#### アクション
1. **HTMLの解析とテキスト抽出**
   - 各政党の公約HTMLファイルからテキストを抽出
   - ナビゲーション・スタイル情報などのノイズを除去
   - 段落ごと/セクションごとのテキスト区切りを保持

2. **テキスト正規化**
   - 全角・半角の統一
   - 改行・余分な空白の正規化
   - 重複表現の除去

3. **選挙結果データの構造化**
   - テキストファイルから当選者数・立候補者数を抽出
   - 当選率（当選者数 / 立候補者数）を計算
   - 選挙区別（衆議院／参議院）データとして整理

#### 成果物
- `2025_house_policies/` ディレクトリ: 衆議院公約テキストデータ
  - 構成: 政党ごとにテキストファイルを作成
  - ファイル命名: `{party_name}.txt`（例: `自民党.txt`, `社民党.txt`）
  - 内容: 各政党の公約テキスト（未分類）

- `2025_senate_policies/` ディレクトリ: 参議院公約テキストデータ
  - 構成: 政党ごとにテキストファイルを作成
  - ファイル命名: `{party_name}.txt`（例: `自民党.txt`, `立憲民主党.txt`）
  - 内容: 各政党の公約テキスト（未分類）

- `election_results_normalized.csv`: 選挙結果データ
  - カラム: `election_type, party, candidates, elected, election_rate`
  - 内容: 衆参別・政党別の候補者数、当選者数、当選率

#### 注釈
- **課題抽出なし**: Phase 1 では単純なテキスト抽出・整形のみ
- **分類なし**: ポジネガ判定や課題カテゴリー分けは Phase 2 で実施

### 3.2 Phase 2: ポジネガ統合型の課題抽出と分類

#### 目標
- 公約テキストから課題を抽出し、**各課題に対する政党のポジション（肯定/否定/改善案）を同時に把握**
- ポジネガを含めた意味的な課題分類を実現
- 衆参の選挙性質差を考慮した課題の統合

#### アクション

##### 3.2.1 形態素解析とポジネガ分析の統合

1. **テキスト前処理と形態素解析**
   - 日本語形態素解析（janome/MeCab）で名詞・動詞を抽出
   - 修飾関係の抽出（係り受け解析）
   - 修飾構造を保持（例: 「強化する」「廃止する」「維持する」）

2. **ポジネガ感情の分析**
   - **辞書ベース手法**: 日本語感情辞書（例: ポジ辞書）を使用
     - 各キーワード周辺（±2文節）の極性語を検出
     - 極性スコア（-1.0 ~ +1.0）を付与
   - **コンテキスト分析**: キーワードの出現文脈から意味を判定
     - 「問題を解決する」→ 課題「問題」に対し肯定的アプローチ
     - 「規制を撤廃する」→ 課題「規制」に対し否定的アプローチ
   - **多値分類**: 単純な極性スコアでなく、政策的アプローチを分類
     - ポジティブ（強化/推進/拡大）
     - ネガティブ（廃止/削減/制限）
     - 改善案（改革/工夫/代替案提示）

3. **出現パターンの標準化**
   - 同一課題の異なる表現を統合
   - 課題キーごとにポジネガ情報を集約

##### 3.2.2 トピック分析による自動課題抽出と意味的統合

1. **トピックモデリング（BERTopic / LDA）**
   - 衆参合算のテキストに対してトピック分析を実施
   - トピック数の目安: 15-25（統計検定・コヒーレンススコアで最適化）
   - 出力: 各トピックの関連キーワード（ウェイト付き）

2. **トピック内のポジネガ統合**
   - 各トピック内のキーワードに対し、ポジネガスコアを付与
   - トピック極性スコア = （キーワード極性スコア × ウェイト）の平均
   - **トピックの性質分類**:
     - 推進型: 「強化」「拡大」「導入」系
     - 制限型: 「削減」「廃止」「制限」系
     - 改革型: 「改革」「工夫」「変更」系

3. **トピック→分類フレームワーク への自動割り当て**
   - 分類フレームワーク（例：経済・雇用、社会保障など）を事前定義
   - 各トピックの主要キーワード群から、最も関連性の高い分類を自動選定
   - 方法: コサイン類似度で決定

##### 3.2.3 衆参データの統合分析（選挙性質を考慮）

1. **選挙性質の記録**
   - 衆議院: 全国区、3年ごと、小選挙区制
   - 参議院: 地方区・比例区、6年ごと、比例代表制
   - 各課題について「衆議院で言及」「参議院で言及」をフラグで記録

2. **時系列的公約変化の把握**
   - 同じ政党が衆参両方に出馬している場合、公約の変化・継続性を比較
   - 変化パターン:
     - **継続型**: 同じ課題が衆参両方で言及（重要課題の指標）
     - **強調型**: 衆議院では言及なし、参議院で新規言及（時間経過による優先順位変更）
     - **後退型**: 衆議院で言及、参議院では言及なし（優先度低下）

3. **課題カテゴリーの作成**
   - 共通課題: 衚参両方で言及かつ同じ極性
   - 新興課題: 参議院で新規言及
   - 衆院重視課題: 衞議院で複数政党が言及
   - 参院地域課題: 参議院で言及、地域特性あり
   - 極性分裂課題: 同じ課題で衚参間で極性が反対

#### 成果物

- `2025_extracted_topics.csv`: 抽出されたトピック一覧
- `2025_issue_polarity_mapping.csv`: 課題とポジネガの対応
- `2025_classified_policies.csv`: 分類済み公約データ（ポジネガ統合）
- `2025_issue_cross_analysis.csv`: 衆参統合分析結果
- `2025_policy_analysis_report.md`: 詳細分析レポート

### 3.3 Phase 3: 多角的課題重要度評価（人気度排除）

#### 目標
- **出現度のみに依存しない、多角的な重要度評価**を実施
- 課題の社会的影響度・緊急性・実行可能性など、複数の観点から総合評価
- リサーチクエスチョンの候補となるにふさわしい課題を特定

#### 評価指標の設計

**A. 政治的広がり度** (w=0.15)
- 課題を言及している政党数 / 全政党数（0-1）

**B. 政策的多様性スコア** (w=0.20)
- 同じ課題に対する異なるアプローチ（肯定/否定/改革）の種類数 / 3

**C. 緊急性スコア** (w=0.15)
- テキスト内の「喫緊」「急ぐべき」などの表現出現度
- 時間的制約の記述有無
- スコア範囲: 0-1

**D. 社会的インパクト潜在性スコア** (w=0.20)
- 影響対象の広さ（「全国民」など）
- 影響範囲（複数分野にまたがるか）
- 具体的施策の記述有無
- スコア範囲: 0-1

**E. 選挙横断性スコア** (w=0.10)
- 衚参両方で言及: 1.0
- どちらか一方: 0.6

**F. 政策実行難度スコア** (w=0.10)
- 予算配分の記述あり: +0.3
- 法律改正/制度設計の具体案あり: +0.3
- 実施タイムラインが記述: +0.2
- 利害関係者調整の言及: +0.2
- スコア範囲: 0-1

**G. 統計的根拠性スコア** (w=0.10)
- データ引用あり: 0.8-1.0
- 定性的記述のみ: 0.3-0.5

#### 重要度スコアの統合計算

```
総合重要度スコア = 
  0.15 × (政治的広がり度) +
  0.20 × (政策的多様性スコア) +
  0.15 × (緊急性スコア) +
  0.20 × (社会的インパクト潜在性) +
  0.10 × (選挙横断性スコア) +
  0.10 × (政策実行難度スコア) +
  0.10 × (統計的根拠性スコア)
```

#### 詳細分析

1. **出現度ランキングとの比較**
   - Phase 2 での出現度による単純ランキング
   - Phase 3 の総合重要度スコアによるランキング
   - 差異分析と可視化

2. **政党人気度との関連性分析**
   - 各課題について「言及している政党の平均当選率」を計算
   - 相関係数を計算して人気度の影響を定量化

3. **感度分析（Sensitivity Analysis）**
   - 各重みパラメータを ±0.05 変動させてランキングの変化を観測
   - ロバスト性の確認

4. **極性別の重要度分析**
   - ポジティブ施策の課題 vs ネガティブ施策の課題の分離
   - 各グループの重要度スコア分布の比較

#### 成果物

- `2025_issue_importance_multidimensional.csv`: 多角的重要度評価結果
- `2025_ranking_comparison.csv`: 出現度 vs 総合スコアの比較
- `2025_sensitivity_analysis.md`: 感度分析レポート
- `2025_issue_importance_report.md`: 詳細分析レポート

### 3.4 Phase 4: リサーチクエスチョン（RQ）の設定

#### 目標
- Phase 3 の分析結果に基づく、複数の候補 RQ を設定
- コンペティション出題の要求に対応した研究設計
- 分析スコープの明確化と実行可能性の確認
- **重要**: 最終的なリサーチクエスチョン決定時には、SSDSE のデータで実際に分析可能な内容であることを確認する

#### アプローチ

**ステップ1: 課題プロファイルの作成**

Phase 3 で選抜された上位課題（総合スコア上位5-7課題）について：
- 課題の定義と背景
- 各指標別スコア
- 衆参間での言及パターン
- ポジティブ/ネガティブ/改革案の内訳
- 関連する統計データ
- 先行研究における位置付け

**ステップ2: RQ候補の設定**

各課題について、3-4個の異なる視点から RQ を設定：

1. **課題の現状分析型 RQ**
   - 「○○政策課題の現状と課題構造は何か」

2. **政策比較型 RQ**
   - 「政党間でどのような異なる対案が提示されているか」

3. **実行可能性検証型 RQ**
   - 「提案された政策の実行可能性と課題は何か」

4. **社会的影響型 RQ**
   - 「この政策課題の解決が社会経済にもたらす影響は何か」

**ステップ3: RQ の精緻化と検証**

選定した RQ について、以下の要素を整理：

| 要素 | 説明 |
|------|------|
| Research Question | 明確な問い文（1文） |
| Sub-questions | 3-4個の下位質問 |
| Hypotheses | 想定される答えのバリエーション |
| Analysis Method | 使用する分析手法 |
| Data Sources | 政策テキスト、統計データなど |
| Expected Findings | 予想される結果 |
| Research Contribution | コンペティション評価観点での価値 |
| Feasibility Check | 実行可能性の確認 |
| **Analytical Feasibility** | **SSDSE データで実際に分析可能か確認**<br/>- 必要なデータが入手可能か<br/>- 分析方法が実装可能か<br/>- 時間・計算資源の制約を満たすか |

#### 成果物

- `2025_issue_profiles.md`: 上位課題のプロファイル（5-7課題）
- `2025_RQ_candidates.md`: RQ候補の詳細記述
- `2025_selected_RQ.md`: 最終選定 RQ（1-2個）と実行計画

## 7. 注釈・留意点

### 7.1 ポジネガ統合分析の方法論的考慮

本分析における「ポジネガ統合」の意図：
- 課題に対する肯定的施策（推進/強化）と否定的施策（廃止/削減）の両方を価値中立的に捉える
- 政策的な議論の複雑性をむしろ研究対象として認識
- 対立構図そのものが研究価値のある課題の指標

### 7.2 選挙性質への配慮

衚議院と参議院の選挙制度差：
- **衚議院**: 全国一律、3年ごと、小選挙区制
- **参議院**: 地方区・比例区、6年ごと、比例代表制

分析への反映：
- 参議院で言及される課題は、地域視点を含む可能性が高い
- 衚議院では全国的な関心が高い課題が強調される
- 両方で言及 = より客観的な重要課題の可能性

### 7.3 分析の限界と補完方法

- **公約は実行可能性が不確定**: Phase 3 で「政策実行難度スコア」として部分的に対応
- **テキスト分析は言及度を計測**: 統計データでの検証が必要
- **補完方法**: 客観統計データ、先行研究との照合、専門家インタビュー

### 7.4 SSDSE データでの分析可能性の確認

リサーチクエスチョンの最終決定時には、以下の観点から SSDSE データでの分析可能性を必ず確認する：

**確認項目**:
1. **データ利用可能性**
   - 必要なテキストデータ（政策テキスト）が SSDSE に含まれているか
   - 統計データ・参考データが入手可能か
   - データの品質・完全性は十分か

2. **分析実装可能性**
   - 提案された分析手法を Python などで実装可能か
   - 計算量は現実的な範囲内か
   - 必要なライブラリ・ツールが利用可能か

3. **スコープの現実性**
   - 設定されたサンプルサイズ（政党数、課題数、テキスト量）で分析可能か
   - 分析期間（6-9週間の枠組み内）で完了可能か
   - 計算リソース（メモリ、CPU）の制約を満たすか

4. **代替案の検討**
   - もし上記の確認で問題が生じた場合、RQ の修正・スコープ縮小などを検討
   - 実現不可能な RQ は候補から除外

**実行方針**:
- Phase 4 で RQ 候補を複数設定した上で、このチェックを実施
- 確認結果を根拠として、最終 RQ（1-2個）を絞り込む
- 絞り込みプロセスを `2025_selected_RQ.md` に詳細に記録
