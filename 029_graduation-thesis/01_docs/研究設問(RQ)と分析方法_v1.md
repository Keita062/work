# 研究設問（RQ）と分析方法 v1

作成日：2026-10-19
位置づけ：卒論（案件ID 029）における「What」の具体化ドラフト。ここで決めたRQをもとに、次段階でアーキテクチャ（How）を設計する。

## 1. 研究目的（大枠のWhat）

AIコーディングエージェントの利用において、
- **① エピソード内**：1つの依頼が解決（または放棄）するまでの、ターンの連鎖における人の入力・AIの出力・人の反応の相互作用パターン
- **② エピソード間**：利用期間（週など）が進むにつれて、エピソードの特性（ターン数・終端の種類・反応の強さなど）がどう変化するか

の両方を明らかにする。

## 2. 分析の単位・定義

| 用語 | 定義 |
|---|---|
| ターン | 「人の入力 → AIの出力 → 人の反応」の1往復 |
| エピソード | 同じ依頼に関するターンの連鎖。解決・放棄・未解決のいずれかで終端する |
| 終端タイプ | 承認で終了／放棄で終了／未解決のまま中断 の3分類（暫定） |

**エピソード境界の暫定ルール（作業仮説）**
- 一定時間（例：15〜30分）の無操作でエピソード終了とみなす時間ギャップ方式を暫定採用する
- 妥当性（依頼内容が実際に切れているか）は、アーキテクチャ設計・実装段階で検証し、必要なら見直す

## 3. 具体的なRQと分析方法

### ① エピソード内：ターンの連鎖における相互作用パターン

| RQ | 知りたいこと | 分析方法（案） |
|---|---|---|
| RQ1-1 | AIの出力特性（長さ・出力タイプ［コード／説明／質問／ツール呼び出し］・ツール呼び出しの成否）は、直後の人間の反応タイプ（承認／修正／追加質問／放棄）とどう関連するか | ターンごとに出力特徴量と次ターンの反応タイプを抽出し、クロス集計・多項ロジスティック回帰で関連を検定 |
| RQ1-2 | 1エピソードが解決に至るまでのターン数の分布はどうなっているか。ターン数が多いエピソードにはどんな特徴があるか | エピソードごとのターン数を記述統計。ターン数で群分け（例：1ターン完結／3ターン以上）し、群間でターンごとの反応文字数・反応タイプの変化を比較 |
| RQ1-3 | エピソードはどのように終端するか（承認・放棄・未解決の割合）。終端タイプとターン数・出力タイプに関連はあるか | 終端タイプの割合を記述。終端タイプ別にターン数・出力タイプの分布をカイ二乗検定で比較 |
| RQ1-4 | ターンが進むにつれて（エピソード内で）、人間の反応の強さ（修正指示の文字数・具体性）はどう変化するか（エスカレーションか、簡略化か） | エピソード内のターン位置を横軸、反応文字数／反応タイプを縦軸とした推移分析。個人差を考慮した混合効果モデルでトレンドを検定 |

### ② エピソード間：時間的変化（学習・定着効果）

| RQ | 知りたいこと | 分析方法（案） |
|---|---|---|
| RQ2-1 | 利用期間が進むにつれて、1エピソードあたりの平均ターン数は減少するか（学習・定着効果） | 週ごとにエピソード単位のターン数を集計し、週を説明変数とした混合効果モデル（個人差をランダム効果で考慮）でトレンドを検定 |
| RQ2-2 | 利用期間が進むにつれて、エピソードの終端パターン（承認で終わる割合）は変化するか | 週ごとに終端タイプの割合を集計し、ロジスティック回帰（週を説明変数）でトレンドを検定 |
| RQ2-3 | 利用期間が進むにつれて、依頼（初回入力）の特徴（文字数・具体性）は変化するか | 週ごとに初回入力の文字数・具体性指標の分布を比較し、トレンド検定 |
| RQ2-4 | 利用期間が進むにつれて、依頼のカテゴリ分布（実装・デバッグ・設計相談など）は変化するか | 依頼内容をカテゴリ分類し、週ごとの分布変化をカイ二乗検定・時系列で確認 |
| RQ2-5 | これらの時間的変化パターンに個人差はあるか | 個人をグルーピング変数とした混合効果モデルで個人差（ランダム効果）の大きさを評価 |

## 4. 今後の検討事項（アーキテクチャ設計に引き継ぐ論点）

- エピソード境界判定ルール（時間ギャップ方式）の妥当性を、実データで検証する方法
- 「反応タイプ」「依頼カテゴリ」「出力タイプ」の分類基準（ルールベースか、LLMによる自動分類か）
- どのログ項目から上記の特徴量を抽出できるか（ツール選定＝Howに依存するため、How検討時に再確認）
- 個人差分析を行う場合、研究室メンバー複数名からの収集・同意・仮名化の手続きが必要（`00_context/`の教授向け提案書を参照）
